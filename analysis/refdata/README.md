# Reference data

`placeholder/` is approximate and hand-made, so ward and neighbourhood assignments near edges will be wrong. Each file carries `"placeholder": true`, and that marks every output as placeholder.

To use real data, put the files in a folder and update `[stages.locate]` in `analysis/config.toml`. Leave out `"placeholder": true`.

- **Areas**: one `[[stages.locate.areas]]` block per GeoJSON file of Polygon or MultiPolygon features. `name_property` is the property holding the name, and `field` is the output field. For example, the City's ward file gives `field = "ward_id"`, and its neighbourhoods file gives `field = "neighbourhood_id"`. Set `searchable = true` to let area names be matched in post text.
- **Infrastructure**: one GeoJSON file of Point or LineString features. `type_property` becomes `infrastructure_type`; the frontend filters on `TTC`, `Schools` and `Roads`. `name_property` becomes `asset_name`.
- **Places** (`places.json`): `{"places": [{"name", "kind", "lng", "lat", "radius_m", "match_all" | "aliases"}]}`.
  - `kind` is `intersection` or `landmark`.
  - An intersection matches when every word in `match_all` appears in the text, for example `["queen", "spadina"]`.
  - A landmark matches any phrase in `aliases`.
  - The nearest intersection or landmark also becomes the display address.

The placeholders were generated by a one-off script, so edit the files directly.
